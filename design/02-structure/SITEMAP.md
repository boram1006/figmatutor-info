# LGE AX Hackathon 2026 — 웹서비스 전체 기획 (사이트맵 + 권한 + 상태 + 의존관계)

v1~v5 릴리즈 PDF의 모든 노란 박스(PRD)와 화면을 정독해 종합한 문서다.
목적: 새 기획 요청이 들어왔을 때 **그것이 어떤 화면·기능·상태에 영향을 주는지** 판단하는 기준.

- 근거 자료: `design/operations/prd-pdf/`(텍스트 추출 + 렌더 이미지), 노란 박스 PRD 정독.
- 화면 ID 체계: 일반 사용자 지원 흐름 = **A 시리즈**, **AI 심사 관리 기능 = J 시리즈**. 사람 심사 화면(v1 1차/최종 심사)은 J 시리즈와 별개다.
- 이 문서는 "기존 양산 화면"의 기획 이해용이다. 새 화면 제작은 `docs/new-screen-workflow.md`를 따른다.

## 1. 권한(롤) 개요

계정 종류는 **2종**이다.

1. **일반 계정**
2. **관리자 계정**

`심사자`는 별도 계정 종류가 아니다. 관리자가 특정 일반 계정에 회차/기간 단위로 **심사자 권한**을 부여하면, 해당 일반 계정이 사람 심사 기능을 사용할 수 있다.

| 구분 | 정의 | 접근/진입 | 대표 기능 |
| --- | --- | --- | --- |
| **일반 계정** | 참가자·사내 임직원이 사용하는 기본 계정 | 일반 GNB | 랜딩, 공지, FAQ, 팀빌딩, 지원하기(A), 발표/수상작, 마이페이지, 최종보고서 제출 |
| **일반 계정 + 심사자 권한** | 일반 계정에 관리자가 일시적으로 심사 권한을 부여한 상태. 별도 계정 타입이 아님 | 심사 권한이 있을 때 사람 심사 기능 노출 | 배정된 지원서의 1차/최종 심사, 점수 입력·저장, 진행률 확인, 최종 검토 및 제출 |
| **관리자 계정** | 서비스 운영용 별도 계정 | 관리자 전용 기능 및 **AI 심사** 메뉴 | 심사자 권한 부여/해제, 공지 작성, 팀빌딩 기간 설정, 결과 발표, 회차 개설, **AI 심사 J-01~J-04**, AI 심사 실행·결과·템플릿 관리 |

### 권한 관계

- **심사자 권한은 일반 계정에 추가되는 임시 권한**이다.
- 심사자 권한 부여/해제 주체는 **관리자**다.
- 사람 심사 기능은 **심사자 권한이 있는 일반 계정**만 사용할 수 있다.
- **AI 심사(J-01~J-04)의 접근 주체는 관리자 계정이다. 심사자 권한으로 접근하지 않는다.**
- 사람 심사와 AI 심사는 목적과 사용자가 다르므로 동일 메뉴/권한 체계로 합치지 않는다.

### 현재 기획에서의 미정 영역

v1~v5 PRD에는 **심사자 권한을 부여/해제하는 관리자 UI 자체는 명시적으로 정의되어 있지 않다.**
필요하면 별도의 관리자 화면으로 신규 기획해야 한다.

```
공지사항                          [v1]
  ├ 공지 목록                     No./제목/중요뱃지, 페이지네이션
  └ 공지 상세                     중요뱃지+날짜+조회수, 작성자=관리자, 일정/장소/준비물
FAQ                              [v1] 아코디언 질문 목록
팀빌딩                            [v1/v4] 상태: 모집예정 / 모집중 / 모집마감
  ├ 팀 카드 목록                  정렬 1)내가 지원한 팀 2)모집중(사용자별 고정랜덤) 3)완료

  │                              카드 하단=포지션별 버튼 [지원하기]/[지원취소하기]/[모집완료]
  │                              목록 최대 3.5개 고정높이 + 내부 스크롤, 카운트다운 타이머

  ├ A-01 내 지원서 리스트          허브 화면. 상태별 카드. phase≠OPEN이면 닫히고 마이페이지가 유일 진입점

최종 합격팀 발표                   [v1] FINAL WINNERS, 순위·상금·수상팀
수상작 발표 랜딩 / 수상작 카드      [기존 design] 수상작 소개 + 서비스 연결
최종보고서 제출                    [v5] 단계별 폼(좌측 스텝 네비) + 최종 심사 제출 패키지

  ├ 지원 현황 탭                  모든 회차 통합 테이블(최신순). 컬럼: 회차/아이디어명/진행상태/제출일시/팀원(수)/관리

  │                              팀원 셀 클릭 → 팀원 관리 모달(정보/추가/삭제). 팀원 추가는 웹앱 1회 로그인 이력 필요
  │                              관리: [지원서 보기](항시) + [팀빌딩](관리자 설정 기간에만 한시 노출)
  └ 팀빌딩 관리 탭
```

## 3. 심사 기능 구조

사람 심사와 AI 심사는 서로 다른 기능군이다.

### 3-1. 사람 심사 — 일반 계정 + 심사자 권한

관리자가 심사자 권한을 부여한 일반 계정이 접근한다.

#### 1차 심사
- 심사위원별로 배정된 지원서 목록 제공
- 목록 정보: 관리번호 / 아이디어명 / 분야 / 심사 상태 / 저장된 총점
- 정렬: 관리번호순 / 점수순
- 상태: 미심사 / 심사중 / 심사완료
- 좌측: 심사 대상 지원서 목록 + 전체 심사 진행률
- 우측: 선택된 지원서 PDF 뷰어
- 하단: 심사표 플로팅 버튼
- 심사표는 바텀시트로 호출
- 점수 입력, 항목별 내 평균, 심사 의견, 총점, 전체 평균 제공
- 저장 후 다음 지원서 이동 가능
- 전체 심사 100% 완료 후 **최종 검토하기**
- 최종 확정/제출 이후에는 점수 수정 불가, 조회만 가능

#### 최종 심사
- 배정 지원서 queue
- 지원서/산출물 확인 영역
- AI 요약은 참고 정보로 제공될 수 있으나 **최종 판단은 심사위원이 수행**
- 최종 심사표 점수 입력/저장
- 심사 진행률 및 남은 지원서 수 표시
- 다음 지원서 이동

> 사람 심사의 핵심은 **심사위원이 직접 원본 지원서/산출물을 보고 점수를 입력·저장·최종 제출하는 흐름**이다.

### 3-2. AI 심사 관리 — 관리자 계정 전용 (J 시리즈, v2)

관리자 계정이 접근한다. 진입: GNB **'AI 심사'** → J-01.

```
J-01 AI 심사 대시보드              관리자 전용
  ├ 회차 선택 드롭다운             예: "2026 LGE AX Hackathon 2nd"
  ├ 요약 카드 4종                 전체 지원서 / AI 심사 현황 / 평균 점수 / AI 심사 템플릿(+심사 실행)
  ├ 채점 항목·가중치              문제정의 / AI적합성 / 사용자가치 / 기술실현성 / 임팩트·ROI / 팀실행력
  ├ 지원서 목록 테이블            심사상태 / 총점 / 액션 + CSV 내보내기
  ├─> J-02 AI 심사 결과 목록/상세
  │     전체/심사완료/심사중/대기/실패
  │     지원서별 AI 심사 결과·총점·항목별 의견·산출물 심사 결과
  │     미완료 시 "AI 심사가 진행중입니다"
  ├─> J-03 AI 심사 템플릿
  │     템플릿 생성/수정/삭제/활성화, 공통 스킬 관리
  │     └─> J-04 심사 템플릿 편집
  │           에이전트/평가항목, 시스템 프롬프트, 사용자 메시지 템플릿, 변수 설정
  └ AX 회의록 요약기               AI 심사 세트와 별도의 보조 AI 기능
```

> **J-01~J-04는 사람 심사자용 화면이 아니다.**
> 관리자 계정이 AI 심사를 실행·모니터링하고 AI 심사 기준/템플릿을 관리하는 운영 기능이다.

## 4. 핵심 상태 머신 (지원서 생애주기)

지원서는 두 관점에서 상태가 표현된다 — **사용자용(A-01)** 과 **마이페이지 요약** 은 라벨이 다르니 주의.

| 국면 | A-01(지원하기) 상태 | 마이페이지 진행상태 | AI 심사(J) 처리 상태 |
| --- | --- | --- | --- |
| 작성 중 | DRAFT (작성중, Gray) | — | — |
| 제출됨 | SUBMITTED (제출완료, Green) | 접수완료 | 대기 / 심사중 |
| 심사 중 | REVIEWING (심사중, Purple) | 진행중 | 심사중 |
| 심사 완료 | REVIEWED (심사완료, Gray) + result | 최종합격 / 탈락 | 심사완료(점수) |

- **A-01 상태별 UI 매트릭스**(배지/문구/CTA/result/⋯메뉴)는 `design/operations/prd-pdf/img/v3-a02.jpg` 참조.
- **상태 전이 트리거**: 제출=사용자 마지막 섹션 "제출" / REVIEWING=phase 전환 서버 일괄 / REVIEWED=관리자 결과 발표.
- **phase** 개념: OPEN(접수중)일 때만 A-01/A-02 접근·삭제 가능. phase≠OPEN이면 지원하기 화면이 닫히고 마이페이지만 진입점.

## 5. 공통 규칙 (전 화면 적용)

- **상태 뱃지 색**: 작성중/미제출/심사완료=Gray · 제출완료/접수완료=Green · 심사중/진행중=Purple · 보조안내=Blue · 강조/실패=Red.
- **상대 시간 표기**: 방금 전 / N분 전 / N시간 전 / N일 전 / 7일↑ "YYYY.MM.DD".
- **로딩/예외**: 로딩=스켈레톤, 에러="데이터를 불러오는 데 실패했습니다"+[다시 시도], 빈 상태=문구+CTA.
- **상단 네비**: 일반 계정은 일반 GNB를 사용한다. 관리자 계정에는 **AI 심사** 등 관리자 전용 진입점이 추가된다. 심사자 권한은 사람 심사 기능 접근 권한을 추가하지만 AI 심사 메뉴를 노출하지 않는다.
- **채점**: 지원서 60(6항목×10, 5회 반복 평균) + 산출물 40 = 100점. 구간 상/중/하로 권고.

### 5-1. 화면 Archetype 매핑

화면 생성·수정 시 아래 Archetype을 참조한다. 상세: `design/03-design-rules/generation/page-archetypes.md`
기존 화면 수정 시 반드시 `design/03-design-rules/generation/existing-screen-modification.md`를 먼저 읽는다.

| 화면 | Archetype | 밀도 |
|---|---|---|
| 홈(랜딩) | A2 Campaign / Celebration | Low~Medium |
| 공지사항 목록/상세 | A1 Editorial / Information | Low~Medium |
| FAQ | A1 Editorial / Information | Low~Medium |
| 팀빌딩 목록 | A3 Entity Browse / Selection | Medium |
| A-01 내 지원서 리스트 | A4 Personal Status / Work Hub | Medium |
| A-02 지원서 입력 폼 | A5 Step Workflow / Form | Medium |
| 1차 심사 결과 발표 | A2 Campaign / Celebration | Low~Medium |
| 최종 합격팀 발표 | A2 Campaign / Celebration | Low~Medium |
| 수상작 발표 랜딩 / 카드 | A2 Campaign / Celebration | Low~Medium |
| A-30 내 지원 현황 | A4 Personal Status / Work Hub | Medium |
| A-31 최종보고서 스텝 폼 | A5 Step Workflow / Form | Medium |
| A-32 최종 심사 제출 패키지 | A9 Submission Package / Readiness | Medium~High |
| 사람 1차 심사 | A7 Evaluation Workspace | Very High |
| 사람 최종 심사 | A7 Evaluation Workspace | Very High |
| 사람 심사 최종 검토/제출 | A8 Final Review / Finalization | High |
| J-01 AI 심사 대시보드 | A6 Operational Dashboard | High |
| **J-02 AI 심사 결과 목록/상세** | **A7 Evaluation Workspace** | Very High |
| J-03 AI 심사 템플릿 목록 | A6 Operational Dashboard | High |
| J-04 심사 템플릿 편집 | A5 Step Workflow / Form | Medium |

> A7 Evaluation Workspace는 사람 심사와 AI 심사 결과 상세처럼 **원본/근거를 보면서 판단·검토하는 고밀도 작업**에 사용한다. 고정 pane 비율을 규칙으로 만들지 않고 기존 화면 geometry를 따른다. 사람 심사 화면을 token/component QA용으로 재해석하지 않는다.

## 7. 의존관계 (변경 시 영향 파악용)

- **phase(접수 상태)** 변경 → A-01/A-02 접근성, 삭제 가능 여부, 마이페이지 진입 경로 전부 영향.
- **AI 심사 채점 항목/가중치** 변경 → 관리자 J-01 요약, J-02 점수 게이지·항목 카드, J-04 템플릿·변수 전부 영향.
- **사람 심사 항목/점수 정책** 변경 → 1차/최종 심사표, 저장/완료 판정, 최종 검토 화면에 영향.
- **상태 머신** 변경 → A-01 UI 매트릭스, 마이페이지 진행상태, J-02 탭 필터가 함께 바뀜.
- **팀빌딩 설정(관리자)** → 팀빌딩 페이지 노출 데이터 + 마이페이지 [팀빌딩] 버튼 노출 기간.
- **회차(해커톤 차수)** → J-01 드롭다운 기준으로 대시보드·목록 전체 재조회, 마이페이지는 전 회차 통합.
- **심사자 권한 부여/해제(관리자)** → 대상 일반 계정의 **사람 심사 기능 접근 여부 + 지원서 배정**에 영향. **AI 심사 J 시리즈 접근 권한에는 영향 없음.** (권한 관리 UI는 아직 기획에 없음 → 신규 필요)
- **관리자 계정 권한** 변경 → AI 심사 J-01~J-04, 심사 실행, 템플릿/공통 스킬 관리 등 관리자 기능 접근에 영향.

> 새 요청이 들어오면 위 의존관계로 "이 변경이 닿는 화면"을 먼저 나열한 뒤 작업 범위를 잡는다.
