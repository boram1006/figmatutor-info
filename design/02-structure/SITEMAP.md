# LGE AX Hackathon 2026 — 웹서비스 전체 기획 (사이트맵 + 권한 + 상태 + 의존관계)

v1~v5 릴리즈 PDF의 모든 노란 박스(PRD)와 화면을 정독해 종합한 문서다.
목적: 새 기획 요청이 들어왔을 때 **그것이 어떤 화면·기능·상태에 영향을 주는지** 판단하는 기준.

- 근거 자료: `design/operations/prd-pdf/`(텍스트 추출 + 렌더 이미지), 노란 박스 PRD 정독.
- 화면 ID 체계: 일반 사용자 지원 흐름 = **A 시리즈**, 심사자/관리자 = **J 시리즈**. (PRD 명시)
- 이 문서는 "기존 양산 화면"의 기획 이해용이다. 새 화면 제작은 `docs/new-screen-workflow.md`를 따른다.

---

## 1. 권한(롤) 개요

| 롤 | 진입점 | 대표 화면 |
| --- | --- | --- |
| **일반 사용자(참가자)** | 상단 GNB: 홈 / 공지사항 / 팀빌딩 / FAQ / 로그인·마이페이지 | 랜딩, 공지, FAQ, 팀빌딩, 지원하기(A), 발표/수상작, 마이페이지, 최종보고서 제출 |
| **관리자/심사자** | 상단 GNB의 **'AI 심사'** 메뉴(일반 사용자에겐 미노출로 추정) | AI 심사 대시보드(J-01) 및 하위 J 시리즈, 공지 작성, 팀빌딩 기간 설정 |

> 관리자/일반의 상단바는 형태가 같고, 관리자는 'AI 심사' 진입점과 일부 작성/설정 권한이 추가된다.
> PRD에서 확인된 관리자 전용 행위: **공지사항 작성**(공지 상세 작성자="관리자"), **팀빌딩 설정기간 지정**(마이페이지 [팀빌딩] 버튼은 관리자가 연 기간에만 노출), **결과 발표**(REVIEWED 전환 트리거="관리자 결과 발표 액션"), **AI 심사 전체(J 시리즈)**.

## 2. 일반 사용자 메뉴 트리

```
홈(랜딩)                         [v1/v4] 히어로 + 카운트다운 + 주요 일정 + 보상, 다크+골드 발표형
공지사항                          [v1]
  ├ 공지 목록                     No./제목/중요뱃지, 페이지네이션
  └ 공지 상세                     중요뱃지+날짜+조회수, 작성자=관리자, 일정/장소/준비물
FAQ                              [v1] 아코디언 질문 목록
팀빌딩                            [v1/v4] 상태: 모집예정 / 모집중 / 모집마감
  ├ 팀 카드 목록                  정렬 1)내가 지원한 팀 2)모집중(사용자별 고정랜덤) 3)완료
  │                              카드 상단=지원여부/본부/아이디어명/지원서보기/현재인원·총인원
  │                              카드 하단=포지션별 버튼 [지원하기]/[지원취소하기]/[모집완료]
  │                              목록 최대 3.5개 고정높이 + 내부 스크롤, 카운트다운 타이머
  │                              예외: 다른 팀 지원 중 [지원하기] → "이미 다른 팀에 지원 중입니다" 팝업
  ├ 팀 지원 모달
  └ 팀빌딩 설정 모달              팀 신청 토글 + 모집 포지션/인원 입력
                                 제약(v4): 기존 팀원 5명이면 팀빌딩 불가, 모집 포지션 수는 기존 팀원 합쳐 5 초과 불가
지원하기 (A 시리즈)               [v3] GNB "지원하기". phase=OPEN·1건↑이면 A-01, 0건이면 A-02로 즉시 이동
  ├ A-01 내 지원서 리스트          허브 화면. 상태별 카드. phase≠OPEN이면 닫히고 마이페이지가 유일 진입점
  └ A-02 지원서 입력 폼            8개 섹션(stepper): 기본정보 + 팀원 테이블 등. 제출은 마지막 섹션에서
1차 심사 결과 발표                 [v4] 다크+골드 "1차 심사 합격을 축하합니다", 합격 아이디어 카드, Top30/Top20 카운트다운
최종 합격팀 발표                   [v1] FINAL WINNERS, 순위·상금·수상팀
수상작 발표 랜딩 / 수상작 카드      [기존 design] 수상작 소개 + 서비스 연결
최종보고서 제출                    [v5] 단계별 폼(좌측 스텝 네비) + 최종 심사 제출 패키지
  └ 스텝: 기본정보 / 서비스정의 / 문제정의 / AI서비스 구현계획 / 신규페이지 /
          활용 Data 및 연동시스템 / 확장가능성 / 기대효과 / 최종 심사 제출 패키지
  └ 제출 패키지 4구성: 기획·보고서 PDF / 발표자료 PDF / 서비스 데모 URL / 소스코드 저장소 (+마감 경고)
마이페이지                        [v1] 탭 구조 (기본 활성=지원 현황)
  ├ 기본정보                      사번(Number)/연락처(Tel 자동하이픈)/소속본부(Single Select)/소속팀명(Text 30)/직급(Text 10)
  ├ 지원 현황 탭                  모든 회차 통합 테이블(최신순). 컬럼: 회차/아이디어명/진행상태/제출일시/팀원(수)/관리
  │                              진행상태 4종: 접수완료 / 진행중 / 최종합격 / 탈락
  │                              팀원 셀 클릭 → 팀원 관리 모달(정보/추가/삭제). 팀원 추가는 웹앱 1회 로그인 이력 필요
  │                              관리: [지원서 보기](항시) + [팀빌딩](관리자 설정 기간에만 한시 노출)
  └ 팀빌딩 관리 탭
```

## 3. 관리자/심사자 메뉴 트리 (J 시리즈, v2)

진입: GNB **'AI 심사'** → J-01. 브레드크럼으로 계층 이동.

```
J-01 AI 심사 대시보드              GNB 'AI 심사'로 접근 (관리자 진입점)
  ├ 회차 선택 드롭다운             예: "2026 LGE AX Hackathon 2nd"
  ├ 요약 카드 4종                 전체 지원서(128) / AI 심사 현황(94·진행중12·실패3) / 평균 점수(52.6/60) / AI 심사 템플릿(+심사 실행)
  ├ 채점 6항목 가중치             문제정의 20% / AI적합성 20% / 사용자가치 15% / 기술실현성 15% / 임팩트·ROI 15% / 팀실행력 15% (지원서=60점, 산출물=40점, 합 100)
  ├ 지원서 목록 테이블            #/아이디어명/본부/지원자/심사상태/총점/액션 + CSV 내보내기
  │                              필터: 심사완료(5회차 모두 완료)/진행중/실패
  ├─> J-02 AI 심사 결과 목록/상세
  │     상단 탭: 전체/심사완료/심사중/대기/실패
  │     좌: 지원서 목록(정렬 관리번호순·총점순, 카드=아이디어명+관리번호+점수/60+상태배지)
  │     우: 심사 상세 — 총점 게이지(52.8/100 + 순위)
  │          점수 구간: 상 80%↑(녹색)=본선 진출 권고 / 중 60~79%(주황)=추가 검토 / 하 60%↓(레드)=기준 미달
  │          심사 총 의견(배지+한줄+본문+Strengths/Risks/Review Notes 3열), 항목별 AI 심사 카드
  │          지원서 심사 탭 / 산출물 심사 탭, 완료일시 "YYYY.MM.DD HH:MM", 이전/다음 지원서 이동
  │          미완료 시 "AI 심사가 진행중입니다"
  ├─> J-03 AI 심사 템플릿           템플릿 카드(생성/수정/삭제) 목록
  │     └─> J-04 심사 템플릿 편집   에이전트 탭 네비(01 문제정의/02 AI적합성…, 활성점●, 미저장 시 경고 모달)
  │           시스템 프롬프트(최대 4000자, {{변수}} 자동완성·레드 하이라이트)
  │           사용자 메시지 템플릿, 변수 설정(변수명 영문숫자언더스코어·중복불가 / 타입 String·Number·Boolean / 기본값 / 필수 / 설명 200자)
  │           변수 피드백: 정상(녹색)/중복(레드)/특수문자(레드)
  └ AX 회의록 요약기               별도 기능(로딩→요약 결과→단계별 AI 의견). 심사 세트 vN 연동
```

## 4. 핵심 상태 머신 (지원서 생애주기)

지원서는 두 관점에서 상태가 표현된다 — **사용자용(A-01)** 과 **마이페이지 요약** 은 라벨이 다르니 주의.

| 국면 | A-01(지원하기) 상태 | 마이페이지 진행상태 | J(심사) 상태 |
| --- | --- | --- | --- |
| 작성 중 | DRAFT (작성중, Gray) | — | — |
| 제출됨 | SUBMITTED (제출완료, Green) | 접수완료 | 대기/심사중 |
| 심사 중 | REVIEWING (심사중, Purple) | 진행중 | 심사 중 |
| 심사 완료 | REVIEWED (심사완료, Gray) + result | 최종합격 / 탈락 | 심사 완료(점수) |

- **A-01 상태별 UI 매트릭스**(배지/문구/CTA/result/⋯메뉴)는 `design/operations/prd-pdf/img/v3-a02.jpg` 참조.
- **상태 전이 트리거**: 제출=사용자 마지막 섹션 "제출" / REVIEWING=phase 전환 서버 일괄 / REVIEWED=관리자 결과 발표.
- **phase** 개념: OPEN(접수중)일 때만 A-01/A-02 접근·삭제 가능. phase≠OPEN이면 지원하기 화면이 닫히고 마이페이지만 진입점.

## 5. 공통 규칙 (전 화면 적용)

- **상태 뱃지 색**: 작성중/미제출/심사완료=Gray · 제출완료/접수완료=Green · 심사중/진행중=Purple · 보조안내=Blue · 강조/실패=Red.
- **상대 시간 표기**: 방금 전 / N분 전 / N시간 전 / N일 전 / 7일↑ "YYYY.MM.DD".
- **로딩/예외**: 로딩=스켈레톤, 에러="데이터를 불러오는 데 실패했습니다"+[다시 시도], 빈 상태=문구+CTA.
- **상단 네비**: 홈/공지사항/팀빌딩/FAQ/로그인(+관리자는 'AI 심사') + 우측 붉은 CTA.
- **채점**: 지원서 60(6항목×10, 5회 반복 평균) + 산출물 40 = 100점. 구간 상/중/하로 권고.

## 7. 의존관계 (변경 시 영향 파악용)

- **phase(접수 상태)** 변경 → A-01/A-02 접근성, 삭제 가능 여부, 마이페이지 진입 경로 전부 영향.
- **채점 항목/가중치** 변경 → J-01 요약, J-02 점수 게이지·항목 카드, J-04 템플릿·변수 전부 영향.
- **상태 머신** 변경 → A-01 UI 매트릭스, 마이페이지 진행상태, J-02 탭 필터가 함께 바뀜.
- **팀빌딩 설정(관리자)** → 팀빌딩 페이지 노출 데이터 + 마이페이지 [팀빌딩] 버튼 노출 기간.
- **회차(해커톤 차수)** → J-01 드롭다운 기준으로 대시보드·목록 전체 재조회, 마이페이지는 전 회차 통합.

> 새 요청이 들어오면 위 의존관계로 "이 변경이 닿는 화면"을 먼저 나열한 뒤 작업 범위를 잡는다.
