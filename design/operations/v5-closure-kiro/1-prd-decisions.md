## B. 확인 완료 (2026-09-25 사용자 결정)

| # | 항목 | 결정 |
|---|---|---|
| Q1 | 재제출 배지 문구·색 | **"재제출 필요" = Warning.** 유저가 반드시 확인하고 제출해야 하는 액션이므로 warning 계열 semantic 토큰 사용 (성공/중립 아님). |
| Q2 | 1차→최종보고서 section mapping | **1차 지원서 7개 항목이 그대로 승계**되고, 최종보고서에는 **5번 "신규 메뉴"만 추가**된다. 5번 신규 메뉴의 추가 정보는 **서버가 내려주며 UI에서 별도 표현하지 않는다.** |
| Q3 | section 완료 판정식 | **서버가 판정해 내려준다. UI에서 판정식을 표현/구현하지 않는다.** (완료/미완료 표시만 서버 값 반영) |
| Q4 | 발표자료 파일 정책 | **AI는 수정을 위해 PPT로 내려준다. 등록은 PDF만 가능**(PPT 뷰어가 없기 때문). 즉 생성물=.pptx(수정용), 업로드 허용=PDF only. |
| Q5 | 소스코드 저장소 | 기획 미확정. **링크 입력칸만** 제공 (provider 제한/검증 없음). |
| Q6 | navigation ownership | **마이페이지 좌측 네비(내 정보 / 내 지원 현황 / 내 팀 / 팀빌딩 지원 현황) 구성이 맞다.** 내 지원 현황 탭에 지원서 목록 → 선택 → 최종보고서 작성. **A-31의 "지원하기" 컨텍스트 표시는 정상.** (원본 `prd-v5/PRD.md` A-30 §1 좌측 네비 기술이 맞으며, 정정 불필요.) |
| Q7 | canonical deadline | **UI에서 timestamp를 표현하지 않는다.** 마감 시간은 기존부터 정의하던 별도 시간 정의를 따른다. |
| Q8 | 화면 ID 네이밍 | 아래 "화면 ID 추천" 참조. |
| Q9 | 공통 loading/error/empty | 로딩·에러는 발생 빈도 낮고 **기존 공통 양식이 있어 화면별로 정의하지 않는다.** empty는 필요하다고 판단될 때만 추가. |
| Q10 | **마감 후 edit/save/submit 잠금 범위** (권장 초안 → 승인만) | 아래 "Q10 권장 초안" 표 참조. PRD 근거로 3종 기본값을 채웠다. **그대로 OK인지, 바꿀 항목만** 알려주면 된다. |

## Q10 확정 — 마감 후 3종 전부 잠금 + 비활성

| 동작 | 마감 후 (확정) | UI 표현 |
|---|---|---|
| **submit** (최종 제출/재제출) | 잠금 — 제출·재제출 불가 | 버튼 "제출 마감됨"(비활성, 잠금 아이콘) |
| **edit** (폼 항목·4종 항목 수정) | 잠금 — 수정 불가 (조회 전용) | 입력/업로드/링크 편집 컨트롤 비활성, 4종 카드 read-only |
| **save** (임시 저장) | 잠금 — 임시 저장 불가 | [임시 저장] 버튼 비활성 |

**마감 도달 시 전체 read-only. 마지막 제출본이 최종본.** GAP-3(DEADLINE_PASSED) 디자인에 3종 잠금을 모두 반영해 패치한다.

## 화면 ID 추천 (Q8)

현재 `A-30 / A-31 / A-32`는 잠정값이다. 최종보고서는 지원 흐름(A 시리즈)의 연장이므로 **A 시리즈를 유지**하되,
지원 폼(A-01/A-02)과 구분되도록 slug로 "최종보고서"임을 드러내는 것을 추천한다.

| 현재(잠정) | 추천 | 이유 |
|---|---|---|
| A-30 | `A-30_final-report-status` | 내 지원현황 탭의 최종보고서 진입점 |
| A-31 | `A-31_final-report-step-form` | 8섹션 스텝 폼 |
| A-32 | `A-32_final-report-package` | SECTION 9 제출 패키지 |

- **번호(30번대) 유지 이유**: 지원 접수(A-0x)와 최종보고서(A-3x)를 번호대로 구분하는 기존 관례와 맞음. SITEMAP의 A 시리즈 일관성 유지.
- 대안: 독립 하위 시리즈 `AR-01/02/03`(Application Report)도 가능하나, A 시리즈에서 분리되면 마이페이지→지원현황→최종보고서 흐름의 연속성이 명명에서 약해진다. **A-3x slug 방식을 권장.**
- 최종 확정은 전체 넘버링 체계 재검토(다른 릴리즈 포함) 시 함께 승인.
