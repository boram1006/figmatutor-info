## 노란 박스 텍스트 (그대로 Figma PRD 노트에 들어갈 내용)

```
[v5 최종보고서 제출 — PRD 확정본 (2026-09-25 업데이트)]

■ 개요
본선 진출 팀이 최종 기획·개발 보고서를 8개 섹션 스텝 폼으로 작성하고,
9번째 단계에서 발표자료·데모·소스코드를 묶어 하나의 패키지로 최종 제출한다.
진입: 마이페이지 좌측 네비 '내 지원 현황' 탭 → 지원서 카드 [이어 작성하기].

■ 화면
- A-30 내 지원 현황 (진입점) : 마이페이지 좌측 네비 탭. 지원서별 상태·진행률 + 작성 진입.
- A-31 최종보고서 스텝 폼 : 좌측 9단계 스텝 네비 + 우측 섹션 폼. SECTION 1/8~8/8.
- A-32 최종 심사 제출 패키지 : SECTION 9/9. 4종 산출물 통합 제출.

■ A-30 상태 (지원서 카드)
- 본선 진행중·작성중 : Red '본선 진행중' 배지 + [이어 작성하기 →]. content completion 7/8부터 시작.
- 제출완료 : Green '제출완료' 배지 + [제출 내용 보기 →].
- 제출완료 · 수정사항 미반영 : Green '제출완료' 유지 + Warning '재제출 필요' + [수정사항 제출하기 →].
- 본선 미진출 : Gray '본선 미진출' 배지 + [제출 지원서 보기 →].
* 재제출은 사용자가 반드시 확인·재제출해야 반영되는 액션이므로 '재제출 필요'는 Warning으로 표기.
* 자동 반영 없음: 제출 후 수정분은 재제출해야 심사 반영.

■ A-31 스텝 폼
- 스텝 네비 9개: 1 기본정보 / 2 서비스정의 / 3 문제정의 / 4 AI서비스 구성계획 /
  5 신규 메뉴 / 6 활용 Data·연동시스템 / 7 확대전개 가능성 / 8 기대효과 / 9 최종 심사 제출 패키지.
- 승계 규칙: 1차 지원서 7개 항목을 그대로 승계하고, 최종보고서에는 '5 신규 메뉴'만 추가한다.
  5번 신규 메뉴의 추가 정보는 서버가 내려주며 UI에서 별도 표현하지 않는다.
- 섹션 완료(✔) 판정은 서버가 내려준다. UI는 서버가 준 완료/미완료 상태만 표시한다(판정식 UI 미구현).
- 스텝 아이콘: 완료=보라 ✔ / 미완료·현재=회색 번호 / 9번=회색 번호 + '4종 통합' 배지.
- SECTION 2~8 내부 폼 필드 구성은 디자인 범위 밖(스텝 네비 섹션명·상태만 다룸).

■ A-32 제출 패키지 (4종)
1 기획/개발 최종 보고서 : [최종 보고서 확인]=SECTION 1~8 통합 팝업 모달(읽기전용) /
  [발표 자료 초안 생성]=AI가 수정용 .pptx 생성.
2 발표 자료 : 등록은 PDF만 가능(PPT 뷰어 없음). AI 생성물은 수정용 .pptx이며, 등록 시 PDF로 올린다.
  미등록 시 드롭존 '최대 50MB · PDF 파일만 업로드 가능'.
3 서비스 데모 URL : URL + [테스트 ↗].
4 소스코드 저장소 : 링크 입력칸만 제공(provider 제한/검증 없음, 기획 미확정).

■ A-32 하단 제출 버튼 상태
- 4종 미충족(최초 제출 전) : '최종 패키지 일괄 제출하기 →' Red primary, 비활성.
- 4종 충족(최초 제출 전) : 동일 라벨, 활성.
- 제출완료·변경없음 : '제출 완료됨 ✓' 비활성(muted).
- 제출 후 수정함 : '변경사항 다시 제출하기 →' Red primary 재활성 + Warning '수정사항 미반영' 안내.
- 마감 이후 : '제출 마감됨' 비활성(잠금).
* [임시 저장]은 마감 전 항시 사용 가능. 임시 저장은 상태를 '제출완료'로 바꾸지 않는다.

■ 마감/잠금
- 접수 마감(별도 정의된 기존 마감 시각 기준) 도달 시 잠금. 마지막 제출본이 최종본.
- 마감 시각 자체는 UI에 timestamp로 새로 표기하지 않고 기존 정의를 따른다.
- [확인 필요] 마감 후 edit(수정)/save(임시저장)/submit(제출) 각각의 잠금 범위는 아직 미확정.
  현재는 submit 잠금('제출 마감됨')만 확정. edit/save 잠금 표현은 확정 후 반영.

■ 공통 규칙
- 상태 배지 색: 완료/접수완료=Green / 진행중=Red / 미제출·미등록=Gray / 재제출 필요=Warning.
- 로딩·에러는 기존 공통 양식을 따르며 화면별로 별도 정의하지 않는다.
- 빈 상태(empty)는 필요하다고 판단될 때만 추가한다.

■ 화면 ID (잠정, 승인 대기)
A-30/31/32는 잠정. 권장: A-30_final-report-status / A-31_final-report-step-form / A-32_final-report-package.
```

## 반영 방식 note

- 위 텍스트는 기존 노란 박스(`20:823`)를 훼손하지 않고 **보충 PRD 노트를 새로 추가**하는 방식으로 캔버스에 넣는다.
  - 이유: 기존 박스 내부 텍스트 노드 구조(어느 노드가 어느 문단인지)를 모른 채 patch하면 위험. 새 노트 추가가 안전하고, 기존 근거도 보존된다.
- 대안(원한다면): 기존 `20:823` 내부를 재추출해 문단별 노드를 확인한 뒤 해당 텍스트만 교체하는 방식. 정확하지만 재추출·노드 매핑 선행 필요.
- 생성 스펙: `spec-create-prd-note.json`.
