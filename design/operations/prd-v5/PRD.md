## 3. A-30 · 내 지원 현황

### 진입/구조
- 마이페이지 좌측 네비: 내 정보 / **내 지원 현황** / 내 팀 / 팀빌딩 지원 현황.
- 본선 진출 지원서가 있으면 최종보고서 카드가 노출된다.
- A-31/A-32 내부에서는 기존 화면처럼 **지원하기 컨텍스트 표시가 정상**이다.

### 상태

| 상태 | 표시 | CTA |
|---|---|---|
| 본선 진행중·작성중 | Red `본선 진행중` + content completion | `이어 작성하기 →` |
| 제출완료 | Green `제출완료` | `제출 내용 보기 →` |
| 제출완료 + 변경 미반영 | Green `제출완료` 유지 + Warning `재제출 필요` | `수정사항 제출하기 →` |
| 본선 미진출 | Gray `본선 미진출` | `제출 지원서 보기 →` |

확정 규칙:
- 최초 content completion = **7/8**.
- 신규 5번 section 완료 후 = **8/8**.
- 제출 후 수정해도 primary state는 `SUBMITTED`를 유지한다.
- 수정사항 미반영은 secondary action-needed state다.
- 제출 후 수정분은 **자동 반영하지 않으며 재제출해야 심사 반영**된다.
- `재제출 필요`은 필수 확인 액션이므로 **Warning semantic**을 사용한다.

상단 안내:
> 10월 16일까지 제출을 완료해주세요. 제출완료 이후에도 접수 마감 전까지는 수정 가능합니다.

로딩/에러는 기존 공통 양식을 사용하고 v5 화면별 별도 정책으로 정의하지 않는다. Empty state는 실제 필요가 확인될 때 추가한다.

## 4. A-31 · 최종보고서 스텝 폼

### 스텝 구성
1. 기본 정보
2. 서비스 정의
3. 문제정의
4. AI서비스 구성계획
5. 신규 메뉴
6. 활용 Data 및 연동시스템
7. 확대전개 가능성
8. 기대효과
9. 최종 심사 제출 패키지

### 승계 규칙
- 1차 지원서 **7개 항목을 그대로 승계**한다.
- 최종보고서에는 **5번 신규 메뉴만 추가**된다.
- 승계된 7개 항목은 read-only가 아니라 수정 가능하다.
- 5번 신규 메뉴의 추가 정보는 **서버가 내려주며 UI에서 별도 규칙을 표현하지 않는다**.
- 최초 completion은 7/8이다.

### 완료 상태
- 완료: 보라 ✔
- 미완료/현재: 회색 번호
- 9번 패키지: 회색 번호 + `4종 통합` 배지 및 하위 4종 상태

**section 완료 판정식은 서버가 판정한다.**
UI는 서버가 내려준 완료/미완료 상태만 표시하며 required/optional 판정식을 구현하지 않는다.

### 디자인 범위
- SECTION 2~8 내부 폼 필드 상세 구성은 v5 디자인 범위에서 제외한다.
- step navigation의 section 이름/상태와 workflow 연결만 다룬다.

## 5. A-32 · 최종 심사 제출 패키지

### 4종 구성

| # | 구성요소 | 확정 동작 |
|---|---|---|
| 1 | 기획/개발 최종 보고서 | `최종 보고서 확인` → SECTION 1~8 통합 **read-only modal**. `발표 자료 초안 생성 (.pptx)` → AI가 수정용 PPTX 생성 |
| 2 | 발표 자료 | **등록은 PDF only**. AI 생성 PPTX는 수정용이며 사용자가 PDF로 변환해 등록 |
| 3 | 서비스 데모 URL | URL + `테스트 ↗` |
| 4 | 소스코드 저장소 | **링크 입력칸만 제공**. provider 제한/검증 없음 |

완료=Green ✔, 미등록=Gray.

### 최종 보고서 확인
- 현재 A-32 위에 modal/overlay로 연다.
- SECTION 1~8 내용을 통합해서 읽기 전용으로 보여준다.
- edit control 없음.
- 닫으면 A-32 context를 유지한다.

### 발표자료 정책
- AI 생성물: `.pptx` (수정용)
- 최종 등록: **PDF only**
- 업로드 안내: `최대 50MB · PDF 파일만 업로드 가능`

### 제출 버튼 상태

| 시점 | 버튼 | 상태 |
|---|---|---|
| 4종 미충족 | `최종 패키지 일괄 제출하기 →` | 비활성 |
| 4종 충족 | 동일 라벨 | 활성 |
| 제출완료·변경없음 | `제출 완료됨 ✓` | muted 비활성 |
| 제출 후 수정 | `변경사항 다시 제출하기 →` | Red primary 재활성 + Warning 안내 |
| 마감 후 | `제출 마감됨` | 비활성 + 잠금 |

- `임시 저장`은 제출과 별개이며 마감 전 사용 가능하다.
- 임시 저장만으로 submitted state가 되지 않는다.

### 마감 후 정책
기존 서비스에서 정의하는 마감 시각을 따른다. v5 UI에 별도 canonical timestamp를 새로 노출하지 않는다.

마감 도달 시:
- **edit 잠금**
- **save 잠금**
- **submit/re-submit 잠금**
- 전체 read-only
- 마지막 제출본이 최종본

## 6. 공통 상태 원칙

- 완료/접수완료 = Green
- 진행중 = Red
- 미제출/미등록 = Gray
- 재제출 필요 = Warning
- Save와 Final Submit은 서로 다른 이벤트다.
- Final Submit만 workflow의 제출 상태를 변경한다.
- 제출 후 수정은 기존 제출본을 삭제하지 않고 `SUBMITTED + CHANGED_AFTER_SUBMIT`으로 표현한다.
