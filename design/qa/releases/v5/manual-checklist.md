# v5 Manual QA Checklist

정본 QA: `qa-cases.yaml`  
정의되지 않은 항목: `qa-gap-audit.md`

이 문서는 실제 사람이 화면을 보면서 **무엇을 조작하고, 무엇이 나오면 Pass인지** 바로 알 수 있도록 작성한 실행용 체크리스트다.  
상세 requirement와 TC 정본은 `qa-cases.yaml`이며, 이 문서는 여러 TC를 사용자 journey 단위로 묶어 실행한다.

## Result
- **Pass**: 아래 통과 기준과 일치
- **Fail**: 통과 기준과 불일치
- **Skip**: 현재 fixture/환경에서 재현 불가
- **Blocked**: PRD 또는 backend 상태가 부족해 expected를 확정할 수 없음

## Journey 1 — 본선 최초 진입 → 7/8 → 8/8 → 제출 패키지 진입

### 시작 데이터
- 본선 진출 팀
- 1차 지원서의 기존 7개 section은 모두 작성 완료
- 최종보고서에서 새로 추가되는 section은 아직 미완료
- 최종 패키지는 아직 제출하지 않은 상태

### 실행

| 순서 | 실행 방법 | 통과 기준 | QA ID | Result |
|---:|---|---|---|---|
| 1 | 마이페이지 → 내 지원 현황으로 이동해 해당 지원서의 최종보고서 카드를 본다. | 카드의 content completion이 **7/8**로 표시된다. | A30-001 | |
| 2 | 카드의 **이어 작성하기 →**를 누른다. | 최종보고서 작성 화면 A-31로 진입한다. | A30-002 | |
| 3 | A-31에서 기존 1~4, 6~8 section을 각각 열어 기존 입력값이 있는지 본다. | 1차 지원서에서 작성했던 기존 7개 section의 데이터가 그대로 표시된다. | A31-001 | |
| 4 | 기존 section 중 하나의 값을 실제로 수정해본다. | 기존 7개 section이 read-only가 아니며 수정할 수 있다. | A31-002 | |
| 5 | 좌측 step 상태를 본다. | 기존 7개는 완료 상태이고 신규 section은 미완료이며 전체 completion은 **7/8**이다. | A31-003 | |
| 6 | 좌측 step 이름을 위에서 아래로 확인한다. | 1~8 content section 뒤에 9번째 **최종 심사 제출 패키지**가 순서대로 표시된다. | A31-005 | |
| 7 | 완료된 step과 신규 미완료/current step의 표현을 비교한다. | 완료 step은 **보라 ✔**, 미완료/현재 step은 **회색 번호**로 구분된다. | A31-006 | |
| 8 | 9번째 최종 심사 제출 패키지 step을 본다. | **4종 통합** 배지와 하위 4종 산출물 상태가 표시된다. | A31-007 | |
| 9 | 신규 section을 완료 상태가 되도록 작성한다. | 전체 content completion이 **8/8**로 바뀐다. | A31-004 | |
| 10 | 다시 A-30으로 이동한다. | A-30 카드도 **8/8**로 동기화되어 있다. | CROSS-002 | |
| 11 | 다시 A-31에 들어가 9번째 step을 선택한다. | A-32 최종 심사 제출 패키지 화면으로 진입하며 앞선 작성 흐름이 이어진다. | A31-008, CROSS-001 | |

## Journey 2 — 제출 패키지 준비 → validation → 저장

### 시작 데이터
- A-32 진입 가능
- 4종 산출물 중 일부는 아직 미등록
- 제출 마감 전

### 준비하면 좋은 테스트 파일
- 정상 PDF 1개: **20MB 이하**
- 경계 PDF 1개: **정확히 20MB**
- 초과 PDF 1개: **20MB 초과**
- 비-PDF 파일 1개: 예) PPTX
- 테스트 가능한 데모 URL 1개
- 서로 다른 provider의 repository URL 2개

### 실행

| 순서 | 실행 방법 | 통과 기준 | QA ID | Result |
|---:|---|---|---|---|
| 1 | A-32에 진입해 제출 패키지 영역을 본다. | **최종 보고서 / 발표 자료 / 서비스 데모 URL / 소스코드 저장소** 4종이 모두 보인다. | A32-001 | |
| 2 | 등록된 항목과 미등록 항목을 비교한다. | 완료 항목은 **Green ✔**, 미등록 항목은 **Gray** 상태로 구분된다. | A32-002 | |
| 3 | 최종 보고서 항목의 **최종 보고서 확인**을 누른다. | 기존 viewer modal이 열리고 최종보고서 내용을 읽기 전용으로 확인할 수 있다. | A32-003 | |
| 4 | 발표자료의 **발표 자료 초안 생성 (.pptx)**을 실행한다. | 수정 가능한 PPTX 초안 생성 workflow가 시작된다. | A32-004 | |
| 5 | 20MB 이하의 정상 PDF를 발표자료로 등록한다. | PDF가 정상 등록된다. | A32-005 | |
| 6 | 비-PDF 파일을 발표자료로 등록해본다. | 최종 발표자료로 등록되지 않는다. | A32-006 | |
| 7 | 정확히 20MB인 PDF를 등록한다. | 최대 허용 크기인 **20MB 파일은 등록 가능**하다. | A32-007 | |
| 8 | 20MB를 초과한 PDF를 등록한다. | 파일이 등록되지 않는다. | A32-008 | |
| 9 | 서비스 데모 URL을 입력하고 **테스트 ↗**를 실행한다. | 입력한 URL에 대한 테스트 액션을 실행할 수 있다. ※ 실패 URL의 오류 처리 방식은 현재 spec gap. | A32-009 | |
| 10 | 서로 다른 provider의 repository URL을 각각 입력해본다. | 특정 provider에 제한되지 않고 링크를 입력할 수 있다. | A32-010 | |
| 11 | 4종 중 하나 이상을 비워둔 상태에서 최종 제출 버튼을 본다. | **최종 패키지 일괄 제출하기 →**가 비활성이다. | A32-011 | |
| 12 | 일부 항목만 입력된 상태에서 **저장**을 누른다. | 저장을 실행할 수 있다. | A32-013 | |
| 13 | 저장 후 화면/상태를 확인한다. | 저장만으로 **제출완료 상태가 되지 않는다.** | A32-014 | |

## Journey 3 — 4종 완료 → 최종 제출 → 제출완료 상태 확인

### 시작 데이터
- A-32의 4종 항목이 모두 준비된 상태
- 제출 마감 전

### 실행

| 순서 | 실행 방법 | 통과 기준 | QA ID | Result |
|---:|---|---|---|---|
| 1 | 4종을 모두 준비한 뒤 최종 제출 버튼을 본다. | **최종 패키지 일괄 제출하기 →**가 활성화된다. | A32-012 | |
| 2 | 활성화된 최종 제출 버튼을 실행한다. | 최종 제출이 완료되고 화면이 제출완료 상태로 전환된다. | A32-015 | |
| 3 | 다른 화면으로 이동했다가 A-32에 다시 들어온다. | 변경사항이 없으면 **제출 완료됨 ✓** 상태이며 재제출을 요구하지 않는다. | A32-016 | |
| 4 | 제출완료 상태의 하단 안내를 확인한다. | **마감 전까지 모든 항목을 수정할 수 있습니다. 수정 후에는 다시 제출해야 합니다.**가 표시된다. | A32-017 | |

### 실행

## Journey 6 — 제출 마감 후

### 시작 데이터
- backend 기준 제출 마감 시각이 지난 상태
- 가능하면 제출 이력이 있는 테스트 계정 사용
- 마감 후 미제출 사용자의 표시 내용은 현재 spec gap이므로 별도 expected를 만들지 않는다.

### 실행

| 순서 | 실행 방법 | 통과 기준 | QA ID | Result |
|---:|---|---|---|---|
| 1 | 마감 후 A-32에 진입한다. | 화면이 `A-32_submission-package_DEADLINE_PASSED` 상태로 표시된다. | A32-021 | |
| 2 | 각 입력 영역을 클릭하거나 수정 가능한지 확인한다. | 전체가 **read-only**이며 내용을 수정할 수 없다. | A32-022 | |
| 3 | 화면의 하단/주요 action 영역을 확인한다. | **저장 / 최종 제출 / 재제출** 액션이 제공되지 않는다. | A32-023 | |
| 4 | 마감 안내를 확인한다. | **제출이 마감되었습니다.**가 표시된다. | A32-024 | |

## 실행 중 Blocked로 남겨야 하는 항목

아래는 테스트를 안 하는 것이 아니라, **현재 PRD만으로 정답을 확정할 수 없어 별도 정책 확인이 필요한 항목**이다.

- A-31 신규 section의 최종 명칭과 상세 입력 항목
- A-31 section 수정 후 저장/persistence 방식
- 잘못된 데모 URL, 접근 불가 URL, 테스트 실패 시 오류 처리
- 확장자와 MIME이 다른 PDF 위장 파일 처리
- 업로드 실패/네트워크 오류/재시도
- 최종 제출 API 실패/중복 클릭/timeout
- 마감 시각의 timezone 및 정확한 경계 처리
- 마감 후 제출 이력이 전혀 없는 사용자의 화면
- repository URL 자체의 형식 validation

상세 내용은 `qa-gap-audit.md`를 따른다.
