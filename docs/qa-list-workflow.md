# QA 리스트 생성 워크플로우

새 릴리즈가 나올 때마다 QA 체크리스트를 Kiro가 생성하고, 사람이 직접 실행·기록하는 흐름.

---

## 역할 분담

| 단계 | 담당 | 설명 |
|---|---|---|
| QA 리스트 생성 | Kiro | PRD + SITEMAP + 이전 릴리즈 패턴 기반으로 TC 초안 생성 |
| 리스트 검토·보완 | 사람 | 누락 케이스 추가, 우선순위 조정, Skip 사유 결정 |
| 실제 QA 실행 | 사람 | 브라우저에서 직접 확인하며 Pass/Fail/Skip 기록 |
| Fail 이슈 정리 | 사람 + Kiro | Fail 항목 설명 보완, 재현 조건 정리 요청 가능 |

---

## 입력

Kiro가 QA 리스트를 생성하려면 다음을 제공한다.

### 필수
- **릴리즈 PRD** — 대상 화면, 상태 머신, UI 매트릭스, 기능 범위
  - 예: `design/operations/prd-v5/PRD.md`
  - 또는 대화에 직접 붙여넣은 PRD 블록

### 선택 (있으면 TC 품질 상승)
- **이전 릴리즈 QA 파일** — 동일 화면의 기존 TC 패턴 재사용
  - 예: `design/operations/qa/ver.1.md` (저장해 둔 경우)
- **변경점 메모** — "이번에 추가된 기능", "기획 변경된 부분"
- **테스트 서버 URL** — 결과 기록 파일에 자동 삽입

---

## 출력

`design/operations/qa/<릴리즈식별자>.md` 파일 1개.

파일 구조:
```

## 메타
```

## 절차

### 1단계 — 화면 목록 확정

PRD에서 대상 화면 ID를 추출한다.

```
SITEMAP §5-1 Archetype 매핑을 참조해
각 화면의 주요 기능 영역(화면 진입 / 목록 / 입력 / 저장 / 제출 / 에러)을 분류한다.
```

### 2단계 — 기능 영역별 TC 생성

각 화면에 대해 아래 **기능 영역 체크리스트**를 기준으로 TC를 생성한다.

#### 공통 영역 (모든 화면)
| 영역 | 확인 항목 |
|---|---|
| 화면 진입 | 정상 로딩, 로딩 실패 + 다시 시도, 빈 상태 |
| 네비게이션 | GNB 메뉴 노출, 현재 페이지 활성 표시, 로고 클릭 |
| 에러 처리 | 500/503 서버 오류 UI, 타임아웃 안내 |
| 텍스트 | 오탈자, 잘못된 정보 없음 |

#### 목록/테이블 화면 (A4, A6, E 계열)
| 영역 | 확인 항목 |
|---|---|
| 데이터 표시 | 컬럼 항목 정확성, 미입력 `-` 표시, 긴 텍스트 레이아웃 |
| 상태 표시 | 미심사 / 심사중 / 심사완료 / 총점 표시 |
| 정렬 | 기본 정렬 기준, 동점 처리, 저장 후 재정렬 |
| 선택 | 강조 표시, 선택 전환 |

#### 입력 화면 (A5, A7, A8 계열)
| 영역 | 확인 항목 |
|---|---|
| 입력 방식 | 증감 버튼, 키보드 직접 입력 |
| 입력 범위 | 최솟값 차단, 최댓값 차단, 0 차단, 문자/특수문자 차단 |
| 상태 변경 | 입력 시 저장 버튼 활성화, 총점 실시간 계산 |
| 저장 | 저장 API 호출, 성공 후 상태 갱신, 실패 시 UI 유지 + 메시지 |
| 저장 안 됨 보호 | 이탈 경고, 저장 후 이동, 취소 |

#### 제출 화면 (A8, A9 계열)
| 영역 | 확인 항목 |
|---|---|
| 제출 버튼 | 조건 미충족 시 비활성, 조건 충족 시 활성 |
| 제출 동작 | 확인 팝업, 취소, 중복 클릭 방지 |
| 제출 성공 | 잠금 처리, 저장 버튼 비노출, 조회 전용 전환 |
| 제출 실패 | 오류 메시지 |

#### 심사/채점 화면 (A7 계열 — J-02)
| 영역 | 확인 항목 |
|---|---|
| 진행률 | 초기 계산, 완료 수 / 전체 수 정확성 |
| 항목 평균 | 내 평균 점수 = 저장된 전체 지원서 기준 평균 |
| 다음 지원서 | 버튼 노출 조건, 이동 동작, 마지막 케이스 숨김 |
| 동시 접속 | 다중 탭 마지막 저장 기준, 새로고침 반영 |

### 3단계 — 우선순위 배정

| Priority | 기준 |
|---|---|
| P1 | 핵심 기능 동작, 데이터 정확성, 사용자 차단 가능 오류 |
| P2 | 상태 표시, UI 일관성, 보조 기능 |
| P3 | 레이아웃 엣지케이스, UX 세부사항 |

### 4단계 — Skip 후보 표시

다음에 해당하는 TC에는 `**재현 필요` 또는 `**별도 확인 필요` 주석을 붙이고 Result를 `QA : Skip`으로 초기화한다.

- 서버 오류(500/503) 재현이 필요한 케이스
- 타임아웃·저장 실패 재현이 필요한 케이스
- 동시 접속·경쟁 상황 (마지막 자리 동시 지원 등)
- 부하 테스트 성격의 케이스
- 기획 변경으로 해당 기능이 제거된 케이스 (`**기획 변경으로 해당 TC 제외`)

### 5단계 — 파일 저장

```
design/operations/qa/<릴리즈식별자>.md
```

릴리즈 식별자 규칙: `v<버전>-<yyyymmdd>` 예: `v6-20261015`

## 이전 릴리즈 패턴 요약 (ver.1~3 분석)

새 TC를 생성할 때 아래 패턴을 기본 골격으로 재사용한다.

### 1차 심사 / 최종 심사 공통 패턴 (ver.1, ver.3)
화면 진입(목록 조회 정상/실패/빈상태, 기본 선택, 진행률) → 목록(표시정보, 상태3종, 선택, 이동, 정렬) → PDF/Loop 뷰어(조회, 페이지이동) → 심사표(호출, 조회, 표시, 진행률) → 점수 입력(방식, 범위, 상태변경) → 총점/평균 → 저장(버튼, 성공, 실패, 보호) → 다음 지원서 → 전체점수 현황보기 → 최종 제출

### 전체점수 현황 패턴 (ver.1, ver.3)
화면 진입 → 테이블(표시정보, 총점 색상) → 점수 입력(테이블 내 직접) → 총점 계산 → 저장 → 정렬 → 지원서 보기 링크 → 미입력 경고 배너 → 최종 제출(버튼 상태, 팝업, 성공/실패) → 페이지 이탈 보호 → 동시성

### 팀빌딩 패턴 (ver.2)
접근 제어(오픈 전/정시) → 상태 관리(마감 처리) → 데이터(정렬, 로딩, 수치) → 액션(지원서 보기, 지원하기, 취소, 대기신청) → 동시성 → 보안(로그인 체크) → UI(카운트다운, 카드, 로딩)

### 발표/결과 화면 패턴 (ver.2)
데이터(합격팀 정보, 탈락팀, 정렬) → 시간(카운트다운 기준/종료/버튼 변경) → 액션(버튼 동작, 중복 클릭) → UI/UX(로딩, 텍스트 오탈자) → API 에러 → 네비게이션 → 부하 테스트

## 사용 예시

```
"v6 PRD 기반으로 QA 리스트 만들어줘"
→ PRD 파일 경로 또는 내용을 제공
→ Kiro가 위 절차대로 design/operations/qa/v6-<날짜>.md 생성
```

```
"최종 심사 페이지 QA 리스트 업데이트해줘, 이번에 자동저장 기능 추가됐어"
→ 변경점을 알려주면 해당 TC 수정 + 신규 TC 추가
→ 기존 Pass/Skip 결과는 유지, 변경된 부분만 갱신
```
