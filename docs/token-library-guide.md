# Figma 토큰 라이브러리 제작 가이드

사용자가 지정한 [Color Primitives 문서](https://www.figma.com/design/doD5Y4xCYCBRZVc1JIZO6F/?node-id=58-1934)를 토큰 문서의 기준으로 사용한다.
이 문서는 지정 프레임을 조사해 정리한 재사용 제작 지침이다. 과거 프로젝트의 조사 파일과 캡처는 템플릿에 포함하지 않는다.
위 링크는 제작 레퍼런스이며 새 프로젝트의 작업 대상이 아니다. 새 작업 대상은 harness.config.json의 figma.fileKey로 지정한다.
조사 범위는 Color Primitives이며 다른 타입의 문서까지 원본에서 확인한 것은 아니다.

## 원본의 규칙과 관찰

- 명시 규칙: 원시 팔레트는 시맨틱 계층의 기반이다. 제품 UI는 원시 값을 직접 쓰지 않고 시맨틱 토큰으로 참조한다 (`58:1940`, `58:1944`).
- 문서 구성: 프로젝트/날짜 → 큰 제목과 계층 설명 → 계열별 제목·사용 지침 → 견본·토큰명·값 카드. 브랜드/뉴트럴/레드/그린/앰버/오버레이 6개 섹션이 있다 (`58:1941`–`58:2031`).
- 14개 견본은 실제 변수에 연결되어 있다. 이름은 `brand-500`처럼 원본 ID를 표시하고 값은 대문자 HEX, alpha가 있으면 8자리 HEX로 표시한다 (`58:1946`, `58:1960`, `58:2040`).
- 관찰된 시각 기준: 흰 바탕, 넓은 여백, 얇은 구분선, 동일한 카드 열. 문서 폭 1280, 본문 좌우 64, 최대 5열, 카드 간격 16, 카드 214×136, radius 10. Pretendard 제목 32/Bold, 섹션 18/SemiBold, 토큰명 13/Medium, 값 12/Regular.

위 치수·글꼴은 시작 레퍼런스이며 고정 계약이 아니다. 원본의 절대좌표 배치나 비대칭 여백을 강제하지 않는다. 프로젝트명·날짜·팔레트·14개라는 개수를 복제하거나 빈 칸을 채우려고 토큰을 늘리지 않는다.

## 하네스에서 적용할 제작 절차

1. **최소 토큰 단계:** 대표 시안에 필요한 토큰만 만든다. JSON의 primitive 실제 값, semantic의 ref 원칙을 유지한다. 전체 문서와 라이브러리 정리는 사용자 방향 선택 이후에 한다.
2. **선택 후:** `npm run tokens:export`로 선택된 override와 추가 토큰을 반영한 실제 데이터를 읽는다. 기존 Figma 변수·문서가 있으면 ID를 확인해 갱신하고 중복 생성하지 않는다.
3. **실제 라이브러리:** primitive 변수 → semantic alias → 텍스트 스타일을 생성한다. 제품 컴포넌트는 semantic 변수와 Text/* 스타일에 연결한다. 문서의 primitive 견본은 해당 primitive에 직접 연결할 수 있다.
4. **Color Primitives 문서:** 원본의 정보 순서를 따른다. 실제로 존재하는 색 계열만 섹션으로 만들고 각 카드에 변수에 연결된 견본, 정확한 토큰 ID, 해석된 값과 alpha를 표시한다. 상단 날짜는 실제 작성/갱신일을 사용한다.
5. **그 외 토큰 문서:** semantic에는 역할명·primitive 참조·해석된 값·용도를, spacing/radius에는 수치와 실제 크기 견본을, typography에는 스타일명·폰트/크기/굵기/행간·문장 견본을 표시한다. 이는 Color Primitives의 문서 패턴을 확장한 하네스 규칙이며 원본에 명시된 별도 가이드로 인용하지 않는다. 실제 사용하는 토큰만 문서화한다.
6. **배치:** 반복 섹션과 카드는 Auto Layout과 내용에 맞는 높이로 구성한다. 원본 폭·간격·타이포 위계를 시작점으로 사용하되 긴 이름이나 설명은 줄바꿈/높이를 조정한다. 시각 가이드용 수치를 제품 토큰에 불필요하게 추가하지 않는다.

## 검증과 증거

토큰 문서를 만들거나 수정한 작업(플러그인 op:create/extract)은 아래 검사를 수행하고
`design/operations/<task-id>/`의 결과에 문서 nodeId, 캡처 경로와 관찰을 남긴다.

- 원본 JSON/선택 결과와 표시 ID·값·alpha·alias 대상이 일치하는지 확인한다. 색 정확성을 스크린샷의 눈대중으로 판정하지 않는다.
- 견본의 실제 변수 바인딩과 제품 UI의 semantic 바인딩을 구분해 확인한다. 글자만 붙인 카드를 변수 생성의 증거로 쓰지 않는다.
- 실제 캡처를 열어 제목/설명 위계, 카드 정렬, 밝은색 견본 식별, 긴 이름의 겹침/잘림을 확인한다. 문제는 캔버스를 고치고 다시 캡처한다.
- 확인한 항목과 제외한 범위를 기록한다. 이 문서의 시각 패턴은 현재 자동 게이트의 검사 항목이 아니므로 `npm run check` 통과만으로 준수했다고 보고하지 않는다.

문서 검토는 기존 컴포넌트·화면 검증을 대신하지 않는다. 기존 입력/선택 지문과 승인 정책은 유지한다.
